# 1단계 권한 마스터 이관 계약

## 원본과 대상

- 원본 기준 테이블은 `TN_CM_AUTH_BASIC`이다.
- 이 단계의 대상 시스템은 `AI`, `AB`, `CY`, `MO`다. 시스템 ID는 `AUTH_ID` 앞 2자리에서 파생한다.
- 원본 `AUTH_NM`, `AUTH_DSC`, `USE_FLAG`를 자르거나 대체하지 않고 대상 권한 마스터에 추가·갱신한다.
- 원본 `AUTH_CLSF_ID`는 가져오기 결과에 보존하지만 권한 분류 연결은 2단계에서 수행한다.
- 기존 로컬 권한, 사용자 부여 이력, 메뉴 허용, 프로그램 기능 허용은 삭제하지 않는다.

## 실행 순서

1. [export_authority_master_ai_ab_cy.sql](sql/export_authority_master_ai_ab_cy.sql)을 승인된 원본 조회 환경에서 읽기 전용으로 실행한다.
2. 컬럼 별칭을 키로 사용하는 JSON 배열로 내보낸다.
3. 원본 담당자가 ID, 명칭, 설명, 사용 여부와 건수를 검토한다.
4. 관리자 권한 마스터 화면에서 JSON 파일을 선택해 시스템별 건수를 확인하고 이관한다.
5. 응답의 `created`, `updated`, `unchanged`, `deferredClassificationIds`를 보관한다.

입력 예시는 실제 원본 값으로만 작성한다. 정식 명칭·설명·사용 여부가 없는 코드 참조나 화면의 임시 표시명은 입력 자료로 사용하지 않는다.

## 검증 규칙

- `authId`: `AI`, `AB`, `CY`, `MO` 중 하나와 숫자 10자리
- `authNm`: 필수, 최대 100자
- `authDsc`: 선택, 최대 200자
- `useFlag`: `Y` 또는 `N`
- `authClsfId`: 선택, 영문 대문자·숫자·밑줄, 최대 50자
- 중복 ID나 한 건의 오류가 있으면 전체 요청을 반영하지 않는다.
- 기존 값과 완전히 같은 행은 변경하지 않으며 권한 버전도 증가시키지 않는다.

현재 저장 계약이 허용하는 길이를 넘는 원본 값은 임의 절단하지 않고 이관 오류로 보고한다. 이 경우 대상 저장 계약을 먼저 확장한 뒤 다시 실행한다.
