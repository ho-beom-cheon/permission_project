# 3단계 연계 권한 신청 활성화

## 적용한 원본 규칙

- `AI0201002002` 선택 시 `AB0204001002`
- `AI0201002003` 선택 시 `AB0204001001`
- `AI0201001002` 선택 시 `AB0204001002`, `AB0204001001`
- `AI0101001001` 또는 `AI0102001001` 선택 시 `AB0102001001`
- SSO 부서 코드가 `610` 또는 `630`인 사용자가 AI 권한을 선택하면 `CY0201004004`

연계는 권한 추가 신청에만 적용한다. 자동 선택된 권한은 원본 화면과 같이 제출 전에 사용자가 해제할 수 있고, 원본 권한을 해제해도 이미 추가된 연계 권한을 강제로 지우지 않는다.

## 활성 조건

- 선택한 원본 권한과 자동 대상 권한은 대상 권한 마스터에 존재하고 사용 중이어야 한다.
- 마스터가 아직 적재되지 않았거나 비활성이면 계획 단계에서 충돌로 알리고 선택 화면을 이전 상태로 복원한다.
- 현재 로컬 조직 또는 명시 SSO 범위에서 이미 유효하거나 신청 대기 중인 자동 대상은 다시 추가하지 않는다.
- 사용자가 이미 유효하거나 신청 대기 중인 권한을 원본으로 다시 선택하면 즉시 충돌로 처리한다.
- 명시 SSO 소속이 있으면 그 부서 코드를 사용하고, 미이관 사용자는 로컬 부서 코드로 호환한다.

## 저장 계약

- 최종 선택 권한은 원본처럼 권한별 독립 신청 한 건으로 저장하고 개별 심사할 수 있다.
- 저장 순서는 `AI`, `CY`, `MO`, `AB`, 그 밖의 시스템 순이며 같은 시스템에서는 권한 ID 순이다.
- 여러 권한 중 하나라도 저장에 실패하면 앞서 기록한 신청, 대기 권한 이력, 처리 이력과 감사 이벤트를 모두 되돌린다.
- 연계 관계를 서버가 제출 시 강제로 복원하지 않는다. 화면에서 사용자가 확정한 최종 선택 집합만 저장한다.

시스템별 약관 조회와 동의 저장은 4단계에서 연결한다.
