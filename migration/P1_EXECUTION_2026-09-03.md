## DIR-SEARCH-001 — 사용자 목록의 명시적 조회 조건

원본 근거: `C:/arisuinfo/src/main/resources/mappers/arisuinfo/cm/usr/usrMngMapper.xml`, `searchUsr`, 29~52행.

- 사용자명은 `LIKE '%' || usrNm || '%'`, 사용 여부는 정확 일치 조건이다.
- 원본에는 업무 사업소→SSO 사업소 매핑과 SSO 사업소·부서 조건이 별도로 있다.
- 신규 `DirectoryService.searchPeople`과 `GET /api/admin/directory/people`에 사용자명·현행 로컬 사업소·사용 여부의 AND 검색을 추가했다. 검색은 기존 `AUTHORITY_READ` 권한을 요구한다.
- 사용자명은 `%`·`_`를 LIKE 와일드카드로 처리하고 나머지 문자는 그대로 비교한다. 실제 Oracle 세션의 언어·정렬 설정까지 확인한 것은 아니다.
- 관리 화면에서 사용자 업무 선택 시 명시적 검색 조건을 표시한다. 다른 업무의 일반 검색과 전체 디렉터리 스냅샷은 유지한다.

검증 항목: 개별·조합·빈 조건·무결과, 사용 중지 사용자, 대소문자·와일드카드, 정규식 기호의 문자 처리, 조회 후 상태 불변, 읽기 권한 거부, 잘못된 boolean 입력.

잔여 차이: 원본 업무 사업소↔SSO 매핑, 부서 검색, 본부/사업소별 서버 조회 범위, `searchUsrList`의 최신 권한 이력 EXISTS 조건과 원본 정렬·전체 컬럼. 따라서 원본 사용자 조회 전체의 동등성 완료로 처리하지 않는다.

## AUTH-GRANT-001 — 현재 승인된 직접 권한의 중복 신청 차단

원본 근거:

- `C:/arisuinfo/src/main/java/arisuinfo/cm/auth/auth/service/impl/AuthAplyServiceImpl.java`, `saveAuthUsr`, 180행 및 210~226행.
- `C:/arisuinfo/src/main/resources/mappers/arisuinfo/cm/auth/auth/authUsrMapper.xml`, `insertAuthUsrAply`, 337~364행.

원본은 사용자·사업소·부서·권한의 최신 이력이 승인 상태이고 오늘이 시작일~종료일에 포함되면 부여 신청 INSERT를 막는다.

신규 구현은 현재 조직의 최신 직접 부여/회수 이력으로 해당 보유 상태를 검사한다. GRANT 요청에 보유 권한이 하나라도 있으면 요청 번호·신청·권한·알림 상태를 바꾸기 전에 충돌을 반환한다. 한 요청의 기준일은 한 번만 계산한다.

검증 항목: 기간 양 끝과 당일, 만료·미래, 최신 회수, 위임·이전 조직, CHANGE에서 기존 권한 유지, 여러 권한 중 하나가 중복인 요청의 무변경, 승인 후 재신청 HTTP 409 및 신청 건수 불변.

잔여 차이: 원본은 신청·승인·반려·회수를 통합 이력에서 `REG_DT`, `AUTH_APLY_SEQ` 순으로 판단한다. 현재 저장 모델은 requests와 assignments가 분리되어 있고 최신 직접 부여/회수는 sequence로 판정한다. 조직도 원본 사업소+부서와 현행 organizationId의 완전 대응이 남아 있다. 이번 변경으로 전체 권한 이력 동등성을 주장하지 않는다.

## 검증 결과

- 변경 전: 자동 테스트 65개 통과, 실패·오류·건너뜀 없음.
- 변경 후: 자동 테스트 80개 통과, 실패·오류·건너뜀 없음. 권한 서비스 테스트는 16개, 신규 사용자 조회 통합 테스트는 6개다.
- 브라우저: 별도 `127.0.0.1:18081` 서버와 메모리 H2에서 관리자 로그인 후 사용자명+HQ+사용 조건의 viewer 1건, 미사용 조건의 무결과, `v%er` 와일드카드 검색, 사업소 탭의 기존 검색 유지·사용자 검색 숨김을 확인했다. 사용자 검색 화면의 배치도 확인했다. 전체 신규 화면·반응형 검증을 완료한 것은 아니다.
- 검증 서버와 임시 브라우저 탭은 종료했다. 기존 8080 서버는 계속 HTTP 200으로 응답한다. 기존 서버에 새 코드를 재배포하거나 재시작하지 않았다.
- `node --check src/main/resources/static/management.js`와 변경 파일 공백 검사를 수행했다. 상세 테스트 로그는 로컬 `target/migration-test.log`, 자동 테스트 보고서는 `target/surefire-reports`에 있다.
- 로컬 Maven 캐시 위치를 명시해 오프라인 실행한다. 사용자 Maven 설정은 변경하지 않았다.

mvn -o '-Dmaven.repo.local=C:\workspace' --batch-mode --no-transfer-progress test
