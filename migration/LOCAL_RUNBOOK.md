# 로컬 실행 및 추가 업무 안내

## 실행

원본 INFO DB 연결 설정은 필요하지 않다. 현재 프로그램은 원본 접속 파일을 읽지 않는다.

```powershell
cd 'C:\workspace\permission_project'
.\mvnw.cmd test
.\mvnw.cmd spring-boot:run
```

기본 주소: `http://127.0.0.1:8080/portal.html`.
현재 검증용 최신 실행본은 `http://127.0.0.1:18080/portal.html`에서 실행 중이며, `target/browser-check`의 합성 저장소를 사용한다.
합성 관리자 `admin / admin123!`, 게시 관리자 `manager / manager123!`, 조회 사용자 `viewer / viewer123!`를 사용한다.
신규 사용자 비밀번호는 12자 이상, UTF-8 기준 72바이트 이하로 입력한다.

패키지 실행: `java -jar target/permission-menu-demo-1.0.0-SNAPSHOT.jar`.

운영 전에는 업무별 전용 권한 및 사업소별 접근 범위를 원본과 일치하도록 추가 이관해야 한다.
원본 상태 코드 자료는 복사하지 않았다. 과업·이슈에는 합성 코드 또는 승인된 코드 정의를 사용한다.

## 저장과 재시작

- 기본 데이터는 프로젝트 안 `data/common-work.mv.db`에 저장한다. 계정·권한·신청·코드·게시글·파일·일정·알림은 재시작 후 복원한다.
- 로그인 세션은 재시작 시 종료되므로 다시 로그인한다.
- 개발 테스트는 메모리 DB를 사용한다. 복원 검증만 `target/persistence-tests/<임의 ID>`에 별도 합성 파일 DB를 만든다.
- 브라우저 검증용 데이터는 `target/browser-check`에 따로 만들었다. 실제 업무 데이터가 아니다.
- `data/`와 `target/`는 Git에서 제외한다. 원본 데이터 이관 수단으로 사용하지 않는다.
- 저장 폴더를 바꾸려면 프로젝트 하위 경로인 `--app.storage.directory=...`를 지정한다. 외부 JDBC URL은 받지 않는다.
- 신규 로컬 DB를 백업하려면 앱을 정상 종료한 뒤 해당 파일을 보관한다. 실행 중 파일을 직접 복제하거나 편집하지 않는다.

## 오류 처리

- `401`: 다시 로그인한다. 비활성화 또는 관리자 세션 만료도 원인일 수 있다.
- `403`: 필요한 업무 권한이 없다. 버튼 표시와 관계없이 서버에서 검사한다.
- `409`: 다른 변경이 있거나 참조/상태 제약에 걸렸다. 최신 목록과 입력을 비교한 뒤 다시 진행한다.
- 첨부는 파일당 10MB 이하다. 게시글은 최대 10개, 운영 업무는 요청/처리 각각 최대 10개다.
- 게시된 약관은 수정/삭제 대신 새 버전을 등록한다.
- 출력문구는 100자 이하, 순번은 중복 없는 양수다. 상세업무 코드의 앞 두 자리는 업무코드와 일치해야 한다.
- 게시판은 신규 생성 후 게시판 화면의 선택 목록에서 연다. 시스템 코드는 분류 정보이며 별도 권한을 부여하지 않는다.

독립 실행과 위 기능의 저장은 구현했지만 전체 ARISUINFO 기능 동등성·운영 배포 검증은 완료되지 않았다.
[구현 현황](IMPLEMENTATION_STATUS.md)의 남은 항목과 검증 범위를 확인한다.
