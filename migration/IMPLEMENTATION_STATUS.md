# 전체 이관 구현 현황

2026-09-02 기준. **전체 이관은 진행 중이며, 원본과의 기능 동등성 검증은 완료되지 않았다.**
원본 INFO DB에 접속하지 않았다. 실제 데이터 조회·복사·수정·DDL 실행도 하지 않았다.
아래 실행·저장·검증은 신규 로컬 저장소와 직접 만든 합성 데이터만 사용한다.

## 저장 계약과 현재 한계

- 기본 저장 파일은 실행 폴더 하위 data/common-work.mv.db이다. app.storage.directory는 프로젝트 하위 폴더로만 지정할 수 있다.
- DataSource는 내부 H2 URL을 직접 구성한다. Oracle 설정이나 원본 접속 파일을 읽지 않는다.
- 업무 상태는 APP_STATE의 JSON 집합, 저장 버전은 APP_REVISION, 첨부 원문은 APP_ATTACHMENT에 저장한다.
- 같은 프로세스에서 업무 변경·감사·첨부를 하나의 JDBC 트랜잭션으로 처리하며 실패하면 실행 상태도 복원한다.
- 이는 **독립 실행을 위한 저장 구현**이다. 원본 Oracle 테이블·제약조건·프로시저·전체 컬럼을 이식한 정규화 스키마가 아니다.
- 전체 상태 비교와 전역 잠금을 사용하므로 대규모 데이터·다중 서버용 저장소 분리, 성능·장애 검증이 남아 있다.
- 감사 이력은 보존되지만 아직 append-only 테이블이나 변경 불가능한 감사 저장소가 아니다.
- 로그인 세션은 현재 프로세스에서만 유지한다. 재시작 후에는 다시 로그인한다.
- 합성 계정을 포함하므로 현재 기동은 demo 프로필과 로컬 사용을 전제로 한다. SSO·운영 배포 완료로 보고하지 않는다.
- 게시판 시스템 코드는 현재 분류 정보이며 시스템별 접근 권한을 대신하지 않는다. 게시판 관리에는 콘텐츠 게시 권한을 사용한다.
- 게시판 첨부 제한은 0~10개, 출력문구는 한 묶음 최대 200행이다. 원본 운영 용량·전체 입력 계약은 추가 대조해야 한다.

## 검증

- Maven 자동 테스트: **65개 통과**, 실패·오류·건너뜀 없음. 게시판 구분 도입 전 저장 형식의 읽기 호환도 검증했다.
- 권한: 승인 전 미부여, 중복 심사, 시스템별 변경, 위임 보존, 오래된 신청 차단, 일괄 실패 무변경, 사용자 단위 회수의 조직·버전 검사.
- 사용자: 계정 생성 실패 시 프로필/카탈로그/저장 상태 롤백, 본인 조직 조작 차단, 사용 중지 후 기존 인증 차단.
- 게시판·첨부: 비공개 질문과 첨부 접근 차단, 다른 사용자 파일 재사용 차단, 답변 권한, 게시 약관 불변성·동의 중복 방지.
- 기준정보·코드: 은행/지점 참조·미사용 전파, 기간 중첩, CSV 수식 처리, 상위별 하위 코드 식별, 버전 충돌.
- 출력문구: 업무/상세코드 관계, 순번 정렬·중복 거부, 100자 제한, 묶음 삭제·재등록 시 오래된 요청 차단, 사업소 조회 조건.
- 게시판 설정: 관리 권한, 새 게시판의 글 분리, 다른 게시판으로 이동 차단, 첨부 수·공지·답변 정책, 조회수와 편집 버전 분리, 중지 후 일반 사용자 접근 차단·기존 내용 보존.
- 도움말: 메뉴 권한, 변경 이력, 현재/과거 버전 첨부 접근 분리, 이전 첨부의 미연결 삭제 차단.
- 운영: 과업 번호, 구분·연월 변경 차단, 완료일 필수, 첨부 권한·연결 보호, 삭제 후 이력 유지.
- 저장: 실제 파일 DB SHUTDOWN 후 다시 열어 계정·코드·게시글·파일·일정 복원. 업무 변경과 BLOB 기록 후 실패시켜 양쪽 롤백 확인.
- 알림·세션: 수신자 격리·읽음 반영, 실제 폼 로그인 세션 만료 후 API 차단.
- JavaScript 16개 파일 구문 검사 통과(기존 관리자/포털 및 신규 화면).
- 실행 JAR 빌드 완료. 이전 검증 서버의 파일 잠금을 해제한 뒤 같은 소스를 재포장했다. 최신 JAR로 18080 포트 기동과 기존 합성 저장소 복원을 시작 로그에서 확인했다.
- 브라우저 확인: 기존 권한 신청→승인→목록, 분류 저장; 이번 작업의 가상 사업소 등록, 가상 사용자 등록 요청, 사용자 목록/폼과 코드 관리 화면 로딩.
- **추가 브라우저 검증은 자동 승인 검토가 사용량 한도로 거부했다.** 공통코드 새 그룹 클릭부터 차단되어 이후 새 화면의 저장·반응형 시각 검증은 수행하지 못했다. API 테스트를 브라우저 검증으로 대체 표기하지 않는다.

## 원본 대응 및 남은 작업

원본의 749개 파일, 147개 화면, 383개 매핑 후보, 493개 SQL/조각 전체를 이식했다고 주장하지 않는다.
inventory는 발견 목록이며 완료 수가 아니다. function-mapping.csv는 원본 컨트롤러별 현재 대응과 차이를 기록한다.
현재 컨트롤러 68개 중 32개에 부분 대응 구현을 연결했고, 36개는 아직 대응하지 않았다. 부분 대응은 이관 완료가 아니며 최종 동등성 확인 수는 0개다.

1. 사용자·사업소·부서·담당업무의 원본 전체 컬럼, SSO 조직 코드, 사업소별 관리 권한 범위, 동시 수정 계약.
2. 권한 원본 이력 테이블과 개별 이력 처리 전체, 조직·메뉴 트리 전체 표시/검색, 원본 위임 업무·사용자별 승인 상세 조건.
3. 공통코드 표시 플래그별 선택지 필터, 원본 삭제 정책의 최종 일치, 출력 양식·엑셀 계약.
4. 기준정보의 빠진 컬럼·추가 관계, 휴일 연간 생성·음력·근무일 계산, 나머지 bsis 모듈.
5. 게시판 마스터 원본 전체 컬럼·자동 번호, 공지 팝업·PDA 구분, Q&A 상태·메뉴 분류, 시스템/유형별 약관·동의 조건. 신규 게시판 구분과 기본 조회수는 구현했다.
6. 과업·이슈의 원본 코드값/화면 검증·특화 검색·출력·오류 팝업, 업무별 별도 운영 권한. 현재 운영 화면은 공통 관리 읽기/수정 권한을 사용한다.
7. 배치 마스터·휴일 지연 실행·스케줄러·업무 실행, 처리일정 원본 집계, 연계·전자결재·전자고지·발송·서식 이력.
8. 현재 알림은 신규 권한 처리 결과의 내부 알림이다. 원본 전체 업무 알림·처리 이력·관리번호 이력과 동일하지 않다.
9. 주소·사용자 등 공통 팝업, 도움말의 원본 구분·통계·팝업·전체 검색 조건, 공통 유틸리티의 전체 대응.
10. SSO·SMS·메일·전자결재·전문·외부 연계는 연결하지 않았다. 승인된 별도 시험 환경/계약이 필요하며 원본 INFO DB 쓰기로 대신하지 않는다.
11. 모든 원본 화면·API·SQL마다 최종 대응 코드와 검증 근거를 연결하는 전수 확인 및 남은 브라우저 검증.

원본 데이터 보호 때문에 기능을 제외한 것이 아니다. 실제 데이터를 가져오지 않는 조건에서 코드·새 저장소·합성 검증을 계속 이관하는 중이다.
